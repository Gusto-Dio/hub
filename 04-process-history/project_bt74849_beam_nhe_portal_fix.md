**ATUALIZAÇÃO 2026-08-11 (mesmo dia, à tarde) — causa raiz #2 na verdade era outra coisa, e já foi CORRIGIDA:** a Tammy respondeu que matriculou manualmente 2 dos 3 casos (`500R7000014i7ZKIAY` e `500R7000014udn7IAA`) sem nenhum problema — ou seja, não era dado ruim, era bug do bot mesmo. Comparando a gravação com o comportamento do bot: **o clique final de seleção do plano não estava fazendo nada na tela** (confirmado ao vivo, debugando o 3º caso ainda "limpo": `NClick_8` executa, seletor acha o elemento, mas nenhuma mudança visual ocorre).

Inspecionando o HTML real da página (salvo pelo usuário em `Beam Benefits.html` no Desktop), a causa é: o seletor do `NClick_8` mira um `<input type="radio">` que é **decorativo** (`aria-hidden="true" tabindex="-1" style="pointer-events:none"`) — parte de um componente customizado (padrão Radix/Headless UI: `<div data-radio-input="true"><button role="radio">...</button><input aria-hidden.../></div>`). O elemento REAL com o handler de clique é o `<button role="radio">` irmão do input. Clicar no input escondido não dispara nada no app.

**Fix implementado em `ProcessLayer/EnterCoverage.xaml`:** adicionado `ui:InjectJsScript` ("Inject Js Script - Click plan radio button") imediatamente ANTES do `NClick_8` original (que ficou ali, agora inofensivo/no-op). O script:
```js
function(n) { var group = document.querySelector("div[role='radiogroup'][aria-labelledby='{0}-header']"); if (!group) { return false; } var firstOption = group.querySelector("button[role='radio']"); if (!firstOption) { return false; } firstOption.click(); return true; }
```
com `{0}` = `individualBenefit.ToLower` (ex: "vision" → busca `aria-labelledby="vision-header"`).

**Armadilha encontrada (documentar pra próxima vez):** a primeira tentativa usou `InputParameter="[individualBenefit]"` no `ui:InjectJsScript` esperando que o valor chegasse como o parâmetro `n` da function JS — deu `TypeError: Cannot read properties of null (reading 'toLowerCase')`, ou seja `n` chegou `null`. **`InputParameter` não bindou o valor da forma esperada** (não confirmado o porquê — pode ser que `n` na verdade receba o elemento do `Target`, não o `InputParameter`). Fix: parou de depender de `InputParameter`/`n` e passou a embutir o valor direto no `ScriptCode` via `[String.Format("...{0}...", individualBenefit.ToLower + "-header")]` — mesma técnica VB já usada nos outros seletores desse arquivo. `uip rpa validate` limpo. Confirmado ao vivo no Studio: agora o plano é selecionado corretamente na tela.
